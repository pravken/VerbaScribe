Ты работаешь на моём Windows-ПК с установленным VerbaScribe (локальная программа расшифровки встреч и
дубляжа). Работа из трёх частей, по порядку: **A** — перейти на Python 3.11 (закрывает уязвимости),
**B** — проверки и одна правка после независимого аудита, **C** — сравнить новые модели озвучки для дубляжа.
После каждой части коротко отчитайся мне и дождись «дальше». Отвечай по-русски. Правила проекта — в
`CLAUDE.md`, прочитай его первым делом.

**Общие условия:**
- Модели и пакеты — только бесплатные и разрешённые для коммерческого использования. Лицензия не та или
  поменялась в новой версии — остановись и спроси меня.
- Мои данные, модели и установленную программу не трогаем: всё в клоне, копиях и временных папках.
- В `main` не пушь, релиз не выпускай, ключ подписи не трогай. Одна тема — один коммит; перед пушем зелёные
  тесты (по коду возврата), для интерфейса — браузерный прогон, просмотр своего диффа.

## 0. Подготовка

1. Спроси меня, где установлен VerbaScribe (папка с `VerbaScribe.exe`, `.venv`, `.venv-dub`). Дальше это `APP`.
2. Клон и ветка от `main`:
   ```
   git clone https://github.com/pravken/VerbaScribe.git VerbaScribe-pc
   cd VerbaScribe-pc
   git checkout -b claude/python-311 origin/main
   ```
3. Копии вместо настоящих данных:
   ```
   mkdir %TEMP%\vs-pc-data
   copy "%LOCALAPPDATA%\VerbaScribe\meetings.db" %TEMP%\vs-pc-data\
   set VERBASCRIBE_DATA_DIR=%TEMP%\vs-pc-data
   set VERBASCRIBE_MODELS_DIR=%TEMP%\vs-pc-models
   set VERBASCRIBE_SKIP_MIGRATION=1
   ```
   Нужные для проверок модели копируй из `APP\models` в `%TEMP%\vs-pc-models`, не меняя оригиналы.
4. Нужны `uv` и Python 3.11 с python.org (подписанный — для Smart App Control):
   `winget install --id=Python.Python.3.11 -e --scope user`, если его нет.
5. Попроси меня закрыть VerbaScribe на время замеров (видеокарта RTX 3090 24 ГБ делится с программой).

## A. Переход на Python 3.11

**Зачем.** `pip-audit` в CI нашёл 12 уязвимостей в `filelock` (CVE-2026-112907…-112915, -112935…-112940). Все
исправлены в `filelock` 4.2.1, а ей нужен Python 3.11. Сейчас они приняты в `.github/workflows/ci.yml` (шаг
`pip-audit`, абзац про `filelock` над ним). Цель — убрать их оттуда. Из облака это не сделать: lock с хешами
собирается с индексом PyTorch (`download.pytorch.org`), а он там закрыт; обновление старых установок надо
проверить на Windows.

### A1. Lock-файл
1. В `requirements.in` 3.10 → 3.11 (шапка и команда), сборка:
   ```
   uv pip compile requirements.in -o requirements.txt --generate-hashes --python-version 3.11 ^
     --python-platform x86_64-pc-windows-msvc --index-strategy unsafe-best-match ^
     --extra-index-url https://download.pytorch.org/whl/cu126 --emit-index-url --upgrade-package filelock
   ```
   Другие версии не поднимай без нужды. Посмотри дифф: если uv сменил что-то ещё, сверь лицензии новых версий с
   таблицей лицензий в README.
2. `pip-audit -r requirements.txt --disable-pip --no-deps`: `filelock` чист. Убери его `--ignore-vuln` и абзац в
   `ci.yml`. Исключения `setuptools` (PYSEC-2026-3447, GHSA-xmj3-9gf7-h52w) зависят от torch — оставь, если ещё нужны.
3. `app/onnx_gpu.py`: в `WHEEL_HASHES` хеш колеса `onnxruntime-gpu` той же версии для `cp311` (PyPI,
   `...-cp311-cp311-win_amd64.whl`). Тест `PinnedDownloadsTest` (`tests/test_safeguards.py`) проверяет `cp310` —
   переведи на `cp311`; нужна ли запись `cp310` дальше — по A3.

### A2. Новые установки
- `setup.bat`: все 3.10 → 3.11 (winget `Python.Python.3.11`, `py -3.11`, `uv venv --python 3.11`, поиск
  подписанного Python в `Python311`).
- `.github/workflows/ci.yml` и `release.yml`: `python-version: "3.11"`, в проверке lock `--python-version 3.11`.
- README (ru и en): упоминания Python 3.10.

### A3. Обновление существующих установок (главное)
Обновление ставит пакеты в ту же `.venv` (`app/updater.py`, около строки 527; `update.bat` так же). Lock на 3.11
в окружение 3.10 не встанет. Нужно:
1. Перед установкой пакетов проверить версию Python в `.venv`. Не 3.11 — собрать **новое** окружение рядом (например
   `.venv-new`) на Python 3.11 (подписанный python.org при Smart App Control, как в `setup.bat`, иначе uv), поставить
   `requirements.txt`; при успехе заменить старое (старое — `.venv-old` до следующего удачного запуска), при ошибке
   ничего не менять, и сообщение говорит, что прежняя версия на месте. Установщик работает при закрытой программе
   (`launch_installer`); `.venv` в списке `PROTECTED`.
2. То же в `update.bat`.
3. Сборка ONNX Runtime для видеокарты (`app/onnx_gpu.py`) лежит отдельно для текущего Python: после смены окружения
   она должна поставиться заново для `cp311`.
4. Окружение дубляжа `.venv-dub` отдельное. Попробуй его на 3.11 (`app/dub_setup.py`, `setup_dub.bat`,
   `requirements-dub.in`; chatterbox-tts 0.1.7 закрепляет свои версии). Встаёт и дубляж работает — переводи (уйдут и
   предупреждения про Pillow 13 в CI); нет — оставь 3.10 и запиши почему.

### A4. Проверки
- `python -m unittest discover -s tests -t .` на 3.11 и `python -m compileall -q app run.py build_exe.py tests`: код
  возврата 0. Браузер: `tests/ui/smoke.mjs` и `tests/ui/scenarios.mjs` (как в `ci.yml`).
- **Чистая установка:** копия клона в пустую папку, `setup.bat`, запуск: расшифровка GigaAM и Whisper на видеокарте,
  анализ через Ollama.
- **Обновление старой установки:** копия `APP` целиком (её `.venv` на 3.10) в отдельную папку; тестовый архив релиза
  из ветки (`git archive`, версия в `app/__init__.py` выше текущей); установка обновлением программы: окружение
  пересоздаётся на 3.11, программа запускается, расшифровка на видеокарте работает. Затем то же с обрывом сети
  посреди установки пакетов: прежняя версия остаётся рабочей.
- Короткий дубляж записи (если `.venv-dub` переведён — и после его обновления).
- В `CHANGELOG.md` (раздел следующей версии, ru и en): переход на Python 3.11, обновление один раз пересоздаёт окружение
  и скачивает пакеты (сколько ГБ — замерь).

## B. После независимого аудита

1. **HTDemucs с закреплённого коммита (Ж2).** Коммит `adefossez/HTDemucs`:
   `python -c "from huggingface_hub import HfApi; print(HfApi().model_info('adefossez/HTDemucs').sha)"`. Впиши его
   `revision=` в оба `hf_hub_download` в `app/dub_worker.py` (как `CHATTERBOX_REVISION`) и убери их из `known` в
   `PinnedDownloadsTest`. Модели дубляжа скачиваются в пустую папку моделей и работают. Отдельный коммит.
2. **Outlook в другой локали (Ж4).** Формат даты Windows — английский (США), затем немецкий: встречи из Outlook на
   сегодня видны, на завтра — нет (`app/calendar_outlook.py`, `ToString('g')` и `Items.Restrict`). Верни мой формат.
3. **update.bat.** В клоне git: обновляется, код возврата верный, в `%TEMP%` не остаётся `verbascribe-update.bat`.
4. **Горячие клавиши диктовки (В3).** «Отключить» у обеих: после перезапуска сочетания не работают и не заняты
   (другая программа может их зарегистрировать).
5. **Сбой окна (В6)** — если есть ПК или виртуальная машина без WebView2 Runtime: программа открывается в браузере, а
   не завершается ошибкой занятого порта. Нет такой машины — так и запиши.

Результаты допиши в `docs/pc-session-audit-report.md`.

## C. Новые модели озвучки для дубляжа

Сейчас в дубляже **Chatterbox Multilingual V2** (`ResembleAI/chatterbox`, `t3_mtl23ls_v2.safetensors`, коммит
`5bb1f6ee58e50c3b8d408bc82a6d3740c2db6e18` в `app/dub_worker.py`, MIT). Код программы здесь не меняем: только
лицензии и замеры.

**Кандидаты** (по обзорам у всех есть русский и клонирование голоса, лицензия разрешает коммерцию — это надо
подтвердить):

| Модель | Почему | Что известно |
|---|---|---|
| **Chatterbox Multilingual V3** | та же семья: меньше всего работы | MIT; по карточке лучше похожесть и меньше выдуманных слов, чем у V2; есть расстановка ударений для русского |
| **Qwen3-TTS** Base 0.6B и 1.7B (Alibaba) | сильный новый кандидат | Apache-2.0; 10 языков, включая русский; клон по ~3 с |
| **VoxCPM2** (OpenBMB, `openbmb/VoxCPM2`) | свежий кандидат | Apache-2.0 по карточке; 30 языков, включая русский |
| **Fun-CosyVoice3** (Alibaba) | проверить | лицензия и русский не подтверждены: сначала карточка, в замеры — только если Apache/MIT и русский заявлен |

**Отброшены, не трать время:** XTTS-v2 (Coqui CPML), веса F5-TTS и русские дообучения на их основе (ESpeech; CC
BY-NC), Fish Speech / OpenAudio и Spark-TTS (некоммерческие), Silero TTS (некоммерческая, без клонирования), HumeAI
TADA (нет русского, лицензия Llama 3.2), Kokoro и LuxTTS (нет русского). `voxtream2-ru` — OpenRAIL с ограничениями
применения: только по моему решению.

### C1. Лицензии по первоисточникам
Для каждого кандидата дословно, со ссылкой: LICENSE репозитория кода (`QwenLM/Qwen3-TTS`, `OpenBMB/VoxCPM`,
`FunAudioLLM/CosyVoice`, `resemble-ai/chatterbox`); карточки моделей на Hugging Face, включая токенизатор речи или
вокодер, если они отдельно; пакет на PyPI и его прямые зависимости (нет ли GPL или некоммерческих), у Chatterbox — и
пакет ударений. Требования к сгенерированному голосу (согласие, маркировка) сравни с `docs/dubbing.md`, раздел
«Consent and marking of generated files».

### C2. Окружения
Каждый кандидат — в **свой** venv во временной папке (`py -3.11 -m venv %TEMP%\vs-tts-<модель>-venv`; если модель
требует 3.10 — на нём), не в `.venv-dub`. Модели — в `%TEMP%\vs-tts-models` (`HF_HOME` на время сессии). Запиши версии
пакетов и коммит каждой модели (`HfApi().model_info(...).sha`).

### C3. Материал
1. Вместе со мной 3 записи из копии базы: мужской и женский голос, одна с шумом или плохим микрофоном. Из каждой — 10–15
   фраз одного участника по `segments` из базы во временную папку (FFmpeg программы или `tools/profile_dub.py`).
2. Образец голоса — 5–10 с чистой речи этого участника, один на все модели.
3. Тексты: те же фразы в переводе на английский (как в дубляже) и на русском (ударения, числа, сокращения, имена);
   плюс 5 фраз с числами и датами («в 14:30, 3 марта 2026 года») и 3 с английскими словами внутри русского.

### C4. Замеры
Для Chatterbox V2 из `APP\.venv-dub` (точка отсчёта) и каждого кандидата:
- **похожесть голоса** — косинус эмбеддингов ECAPA образца и озвучки (`app/diarizer.py`, `_get_ecapa_encoder`);
- **разборчивость** — WER распознанной озвучки (GigaAM v3 для русского, Whisper для английского), отдельно пропущенные
  и выдуманные слова;
- **скорость** — RTF, первая фраза (с загрузкой) отдельно;
- **память** — пик видеопамяти (`torch.cuda.max_memory_allocated`, `nvidia-smi`), помещаются ли рядом Ollama
  (qwen3.5:4b) и распознавание;
- **длительность** — насколько озвучка длиннее или короче оригинала;
- **на слух, со мной** — слепое сравнение 10 пар фраз в случайном порядке без названий моделей; артефакты: обрывы,
  бормотание, чужой акцент, тишина.

### C5. Отчёт
`bench-report/tts-candidates.md`: лицензии с цитатами и вывод; версии и коммиты; таблица по моделям и записям
(похожесть, WER, RTF, видеопамять, длительность); итог слепого сравнения; рекомендация — перейти на Chatterbox V3,
заменить другой моделью, добавить второй движок (какой и какого размера) или ничего не менять, и что нужно для
встраивания (окружение, lock с хешами, закреплённые коммиты, строка в таблице лицензий README).
