# Проверки после аудита на ПК: отчёт

ПК пользователя: Windows 11, RTX 3090 24 ГБ, Ryzen 9 7950X. Ветка `claude/sweet-maxwell-uaextf`, версия 0.5.0.
Всё на копиях: данные в `D:\vs-audit-data*`, модели в пустой `D:\vs-audit-models`, окружения в
`D:\vs-audit-dubvenv` и `D:\vs-audit-torchvenv`. Настоящая папка данных и модели не изменялись
(только чтение: копия базы, журнал, история WebView для поиска `token=`). Релиз не выпускался.

Часть проверок с окном прошла вместе с пользователем. Потом пользователь отошёл, а инструмента для
управления рабочим столом в этой сессии нет. Поэтому проверки, которым нужны окно, звук или
раскладки, частично остались (список в конце).

## 1. Окружение дубляжа с хешами (В10) — сделано

- `requirements-dub.in` — прежний список с пояснениями. `requirements-dub.txt` — lock с хешами (91
  пакет), в заголовке команда `uv pip compile … --extra-index-url …/cu124`. Пакеты без версий получили
  версии: `s3tokenizer 0.3.0`, `spacy-pkuseg 1.0.1`, `pyloudnorm 0.2.0`, `omegaconf 2.4.0`.
- `requirements-dub-chatterbox.txt`: `chatterbox-tts==0.1.7` с хешами PyPI (MIT), ставится с `--no-deps`.
- `app/dub_setup.py` и `setup_dub.bat` ставят оба файла с `--require-hashes`.
- Маркер «устарело» теперь считает хеш обоих файлов. В `app/updater.py` — та же функция, иначе
  обновление сравнивало бы не то.
- Проверка: окружение собрано через `dub_setup._install()` в `D:\vs-audit-dubvenv` за 148 с,
  `_VERIFY_CODE` прошёл. Короткий дубляж (Chatterbox, en, голос из 8 с русской речи): 3,6 с звука за
  18 с, пик видеопамяти 3,35 ГБ.
- **pip-audit** по lock нашёл около 40 уязвимостей, исправить их внутри окружения нельзя:
  - Pillow 12.3 (34 шт.): Pillow 13 требует Python 3.11, окружение на 3.10;
  - transformers 5.2.0 (6 шт.) и diffusers 0.29.0 (5 шт.): их закрепляет chatterbox-tts 0.1.7;
  - setuptools 80.10 (PYSEC-2026-3447): `<81` нужен perth;
  - torch 2.6.0+cu124 в pip-audit не виден (локальная версия). Chatterbox тоже закрепляет torch 2.6.
  
  Поэтому в CI отдельный шаг «pip-audit (dubbing environment)» печатает находки и ставит
  предупреждение, а не валит сборку. Выход — новая версия chatterbox-tts или окружение дубляжа на
  Python 3.11.
- **Не проверено вручную:** перезапуск с изменённой строкой lock и просьба панели о переустановке
  (нужно окно). Логику покрывают тесты `tests/test_updater.py`.
- Замечено: `uv venv --python 3.10 --python-preference only-managed` в моём запуске создал окружение на
  Python из Microsoft Store (`pyvenv.cfg`: `home = …\WindowsApps\PythonSoftwareFoundation.Python.3.10…`).
  Код как раз пытается этого избежать: стоит проверить, почему uv выбрал Store Python.

- **onnx-asr ревизию не принимает.** `asr_onnx._pinned()` подменяет у его резолвера два шага загрузки
  (`_download_config`, `_download_model`) на те же, что в onnx-asr 0.12, но с `revision=`. При
  обновлении onnx-asr эти шаги нужно сверить с `resolver.py`.
- **speechbrain** (`from_hparams`) ревизию тоже не принимает (первая версия правки упала с `TypeError`).
  Закреплённый снимок скачивается в папку модели, `from_hparams` грузит из папки.
- **Chatterbox:** `from_pretrained` сам качает `main`, поэтому модель грузится через `from_local` из
  закреплённого снимка. Осталось: токенизатор Chatterbox для китайского сам скачивает
  `Cangjie5_TC.json` с `main` (в офлайн-прогоне: «Could not load Cangjie mapping»). Это касается
  только дубляжа на китайский.
- **Whisper Turbo:** репозиторий переехал с `mobiuslabsgmbh` на `dropbox-dash`, старое имя
  перенаправляет. Имя в коде оставлено: по нему названа папка прежних загрузок. Если старое имя кто-то
  займёт, закреплённого коммита там не будет, и загрузка не пройдёт, а не подменится.
- **Demucs:** последний коммит `adefossez/HTDemucs` от 31.08.2026 — «Remove license from model card»
  (было `license: mit`, код Demucs на GitHub по-прежнему MIT). По правилу «лицензия изменилась —
  спросить» пользователь решил пока не трогать Demucs. Вариант на будущее — закрепить `bf35a81` (MIT).
- **Проверка:** всё скачано заново в пустой `VERBASCRIBE_MODELS_DIR`:

  |---|---|
  | GigaAM | 11 с |
  | Parakeet | 28 с |
  | Whisper Turbo | 34 с |
  | Whisper large-v3 | 23 мин (медленный узел HF) |

  Расшифровка FLEURS всеми четырьмя моделями даёт тот же WER, что и раньше; разделение по голосам и
  дубляж работают.

## 3. torch 2.11 — сделано

- **Выбор версии.** torch для cu126 есть до 2.14.1, но torchaudio для cu126 — только до 2.11.
  Выбрано `torch==2.11.0+cu126`, `torchaudio==2.11.0+cu126` (2.10 закрывает PYSEC-2026-2286).
- **Совместимость** (пробное окружение `D:\vs-audit-torchvenv`): CUDA доступна, cuDNN 9.10. Тесты —
  325 OK. faster-whisper/CTranslate2 на GPU, onnxruntime-gpu 1.23.2 (сборка программы ставится и
  берёт cuDNN из torch) и speechbrain на GPU — без ошибок.
- **Скорость и точность** (FLEURS, 80 фраз, GPU):

  | Модель | WER ru | ×реального ru, 2.6 → 2.11 | WER en | ×реального en, 2.6 → 2.11 |
  |---|---|---|---|---|
  | large-v3-turbo | 3,97% | 45,5 → 53,8 | 5,82% | 64,8 → 64,8 |
  | large-v3 | 3,84% | 15,1 → 17,4 | 5,65% | 20,7 → 21,0 |
  | gigaam-v3 | 3,46% | 68,1 → 80,9 | — | — |
  | parakeet-v3 | 5,42% | 87,0 → 106,5 | 7,78% | 93,3 → 121,5 |

  WER одинаковый до числа ошибок. Разделение по голосам на том же клипе: 6 голосов, 81 реплика на
  обоих torch.
- `requirements.txt` перегенерирован командой из заголовка. Нижние границы certifi, requests,
  urllib3, idna, charset-normalizer, httpx2 и httpcore2 выполнились при сборке сами, поднимать вручную
  не пришлось.
- **Обновление с 0.5.0.** Установщик обновлений — это код старой версии, и у него зашит индекс cu124.
  Поэтому lock собирается с `--emit-index-url`: строка `--extra-index-url …/cu126` записана прямо в
  `requirements.txt`. Проверено ровно командой установщика 0.5.0 (`--dry-run` против настоящего
  `.venv`): «− torch 2.6.0+cu124, + torch 2.11.0+cu126». Откат пакетов (`_reinstall`) получает оба
  индекса, потому что возвращает torch 2.6+cu124. `setup.bat` и CI переведены на cu126.
- Окружение дубляжа остаётся на torch 2.6+cu124: его закрепляет chatterbox-tts.
- После выхода версии с этим изменением у пользователей обновление скачает около 2,5 ГБ (torch).

   падали с `400 Bad Request`: в настройках `ollama_model = bge-m3`. Это модель эмбеддингов для поиска

   Уже исправлено в ветке параллельно (`f64f044`: модель эмбеддингов не выбирается для текста, ошибки
   Ollama показываются её словами); на ПК стояла 0.5.0 без этого.

   записи 21:18). Причина не разбиралась.
