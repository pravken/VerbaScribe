# Подпись релизов

Программа обновления проверяет `SHA256SUMS.txt`, а по нему — архив релиза. Контрольная сумма доказывает только, что файл дошёл без искажений: тот, кто может опубликовать релиз в репозитории (украденный токен, взломанный аккаунт), опубликует и подходящие суммы. Подпись ключом автора закрывает эту дыру: без секретного ключа подделать её нельзя, а ключ хранится только у вас.

Формат — [minisign](https://jedisct1.github.io/minisign/) (Ed25519), подпись проверяется и вручную. В подписанный комментарий входит тег релиза, поэтому подпись одного релиза не подойдёт к другому.

## Как включить (один раз)

1. **Создайте ключ на своём компьютере**, не в облачной сессии. Скрипт лежит в репозитории (ветка `claude/sweet-maxwell-uaextf`, после слияния — `main`), поэтому команду запускают из папки клона. Подойдёт любой Python 3, пакеты программы не нужны:

   ```
   git clone --branch claude/sweet-maxwell-uaextf https://github.com/pravken/Verbaliox D:\Temp\Verbaliox-key
   cd /d D:\Temp\Verbaliox-key
   python tools\release_key.py generate --out D:\Projects\_Secret_Keys\VerbaScribe\verbascribe-release.key
   ```

   Секрет кладите вне клона (`--out` с полным путём, папка создаётся сама). Скрипт напишет путь к файлу секрета и строку открытого ключа. Клон потом можно удалить.

2. **Секрет — в GitHub.** Откройте репозиторий → Settings → Secrets and variables → Actions → New repository secret. Имя `RELEASE_SIGNING_KEY`, значение — весь текст файла секрета (строка `verbascribe-release-key:…` — префикс остался от прежнего имени программы, так и нужно).

3. **Сохраните файл секрета** в надёжном месте офлайн (менеджер паролей, зашифрованная флешка). Если он пропадёт, придётся выпустить версию с новым открытым ключом, а уже установленные копии примут её только вручную.

4. **Открытый ключ — в программу.** В `app/updater.py` впишите строку из шага 1 в `RELEASE_PUBLIC_KEY = "…"` и закоммитьте. Это можно поручить сессии Claude: передайте ей только открытый ключ, секрет никому не нужен.

С этого момента:

- workflow релиза подписывает `SHA256SUMS.txt` и выкладывает рядом `SHA256SUMS.txt.minisig`. Перед публикацией он сам проверяет подпись ключом из `app/updater.py`. Если секрета нет, а ключ в программе уже есть, релиз не публикуется: иначе его никто не смог бы установить.
- версии программы с ключом ставят обновление только с верной подписью этого релиза. Неподписанный или подменённый релиз отклоняется с сообщением «Подпись релиза не прошла проверку».

Пока `RELEASE_PUBLIC_KEY` пуст, всё работает как раньше: проверяется только контрольная сумма.

## Ручная проверка релиза

С minisign:

```
minisign -Vm SHA256SUMS.txt -P <открытый ключ>
```

Или скриптом из репозитория (берёт ключ из `app/updater.py`):

```
python tools/release_key.py verify SHA256SUMS.txt --tag vX.Y.Z
```

Затем сверьте архив с суммой из `SHA256SUMS.txt` (`Get-FileHash Verbaliox-vX.Y.Z.zip`).
