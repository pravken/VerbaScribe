# Проверка распознавания на видеокарте (0.4.2)

RTX 3090 24 ГБ, Ryzen 9 7950X, Windows 11, ONNX Runtime 1.23.2 (CPU и GPU), onnx-asr 0.12.0. 2026-10-22.

## Итог
- Сборка для видеокарты ставится и подключается, GigaAM и Parakeet реально считаются на CUDA, WER совпадает с процессором до знака.
- Ускорение: GigaAM ×1,5, Parakeet ×2,4–3,2. Узкое место GigaAM — VAD на процессоре.
- Откат на процессор при нехватке видеопамяти работает.
- **Ошибки:** удаление сборки из работающей программы оставляет DLL и ломает статус (п. 4.5); надпись «на видеокарте» в статусе тут же затирается (п. 4.2); диктовка падает на 64-битных хэндлах (исправлено).
- **Английский FLEURS:** клипы en_us записаны очень тихо, VAD выкидывал целые фразы. После нормализации громкости WER на en 6–8% вместо 18–33%, и Whisper оказался **лучше** Parakeet на английском — прошлый вывод «Parakeet для en» неверен.

## 1. Сборка на месте
- `onnxruntime.__file__` → `...\.venv\onnxruntime-gpu\onnxruntime\__init__.py`; провайдеры `Tensorrt, CUDA, CPU`.
- `status()`: `installed=True, active=True`, `error` пуст.
- `uv pip list`: обычный `onnxruntime 1.23.2` на месте; VAD faster-whisper работает.

## 2. Модель на видеокарте
- `_load('gigaam-v3', gpu=True)`: 4 сессии модели с `['CUDAExecutionProvider', 'CPUExecutionProvider']`, сессия VAD — только CPU. Как задумано.
- Отката на CPU нет. Есть только предупреждение ORT «N Memcpy nodes are added to the graph … for CUDAExecutionProvider» (GigaAM — 16 узлов, Parakeet — 2): не ошибка, но часть графа копирует данные между CPU и GPU.
- Видеопамять по процессам `nvidia-smi` на Windows (WDDM) не показывает (`[N/A]`); по общему объёму: +2–2,5 ГБ во время расшифровки.

## 4. Работа в программе
1. Статус «Работает на видеокарте» — есть.
2. Расшифровка GigaAM (21 мин) прошла на GPU: видеопамять +2 ГБ, около минуты. **Но надпись «на видеокарте» пользователь не видит:** `stage_text` «Распознавание речи — GigaAM v3 на видеокарте» сразу перезаписывается прогрессом `_onnx_progress` («Транскрибация: 01:55 из 21:18», `app/transcriber.py`) без пометки устройства. В очереди полный статус виден только во всплывающей подсказке. Значка видеокарты на плашке GigaAM пользователь тоже не заметил (только зелёная точка «загружена»). Освобождение видеопамяти после очереди точно измерить не удалось: параллельно грузились модели Ollama, а по процессам WDDM память не делит. После выгрузки Ollama занято 8,8 ГБ, но эти данные не позволяют отделить GigaAM.
3. Студия с субтитрами на GigaAM: видеопамять не растёт (8,8 ГБ ровно), субтитры на CPU. Расшифровка во время записи их не ломает. В субтитрах встречается сырой токен `<unk>` («ид<unk>т») — его стоит вычищать.
4. Откат: видеопамять занята до 0,4 ГБ свободных, две записи на GigaAM расшифровались без ошибок (на CPU).
5. **Ошибка удаления.** «Удалить» в работающей программе: `shutil.rmtree(..., ignore_errors=True)` не может удалить загруженные DLL, в `onnxruntime-gpu\onnxruntime\capi` остаются `onnxruntime_providers_cuda.dll`, `onnxruntime_providers_shared.dll`, `onnxruntime_pybind11_state.pyd`. `installed()` проверяет только папку `capi`, поэтому после перезапуска: `installed=True, active=False`, флажок снят, статус **«Сборка установлена, но видеокарта недоступна (нет драйвера NVIDIA или библиотек CUDA)»**, кнопки «Установить» нет. Распознавание при этом корректно идёт на CPU (неполный пакет без `__init__.py` обычный onnxruntime не перекрывает). Повторное «Удалить» после перезапуска и «Установить» всё вернули: снова `active=True`, CUDA. Предложение: удалять при следующем запуске (метка) или проверять `installed()` по `__init__.py`, и честно писать «удаление завершится после перезапуска».
6. Субтитры, Whisper и разделение по спикерам работают. **Диктовка падала:** `ctypes.ArgumentError: argument 1: OverflowError: int too long to convert` в `app/dictation.py` `write_clip` → `GlobalUnlock(h)`. Хэндлы буфера обмена 64-битные (например `0x162df4f00b8`), а без `argtypes` ctypes передаёт их как 32-битный int. Исправлено отдельным коммитом (argtypes для `GlobalUnlock` и `SetClipboardData`), проверено 200 записями в буфер подряд. Ошибка не связана с видеокартой.

## 5. Английский FLEURS
Причина не в склейке: медианный пик записей en_us около 0,0086 полной шкалы (−41 dBFS), у ru_ru 0,127. Silero VAD считает тихие фразы тишиной: 15 из 80 фраз покрыты меньше чем на 60%, шесть — на 0%. Каждая такая фраза отдельно, без VAD, распознаётся верно (по всем фразам без VAD Parakeet даёт 8,2%). Снижение порога VAD до 0,3 даёт 16,2%, больший `speech_pad` — 17,2%: этого недостаточно. Исправление в `tools/model_bench.py`: каждая фраза приводится к пику 0,9.

**Для программы:** с тихими записями (далеко от микрофона, низкое усиление) то же будет и у пользователей: GigaAM и Parakeet молча потеряют куски. Стоит нормализовать громкость перед VAD в `app/asr_onnx.py` (как минимум для импорта; запись идёт через loudnorm, кроме случаев, когда очистка отключена).
